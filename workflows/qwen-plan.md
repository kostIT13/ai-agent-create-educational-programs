### ASSISTANT
# ИИ-агент для создания образовательных программ: Prod-ready план

## 🎯 Концепция

Система — **мульти-агентный оркестратор**, который превращает запрос пользователя ("хочу курс по LLM для middle-разработчиков на 40 часов") в полноценный образовательный пакет:

- 📋 Программа курса (модули, темы, тайминг)
- 🗺️ Карта компетенций (таксономия Блума + матрица навыков)
- 📚 Лекционные материалы (конспекты, скрипты, слайды)
- 🧪 Тесты и задания (с рубрикаторами и эталонными ответами)
- 🎨 Визуалы (диаграммы, инфографика, превью)
- 📊 Методические рекомендации

Ключевая идея: **не один LLM-вызов, а граф агентов с ревью-циклами**, где каждый агент специализирован, а критик возвращает работу на доработку.

---

## 🏗️ Архитектура (high-level)

```
┌──────────────────────────────────────────────────────────┐
│                     Frontend (Next.js)                    │
│   Форма запроса → Превью → Редактор → Экспорт (PDF/PPTX) │
└──────────────────────────┬───────────────────────────────┘
                           │ REST / WebSocket
┌──────────────────────────▼───────────────────────────────┐
│              API Gateway (FastAPI + auth + rate-limit)    │
└──────────────────────────┬───────────────────────────────┘
                           │
┌──────────────────────────▼───────────────────────────────┐
│          Workflow Orchestrator (Temporal)                 │
│  ┌─────────────────────────────────────────────────────┐ │
│  │   LangGraph: Planner → Mapper → Generator →         │ │
│  │   Assessor → Visualizer → Reviewer → (loop)         │ │
│  └─────────────────────────────────────────────────────┘ │
└────────┬──────────┬──────────┬──────────┬───────────────┘
         │          │          │          │
    ┌────▼───┐ ┌────▼───┐ ┌───▼────┐ ┌───▼─────┐
    │ LLM    │ │ RAG    │ │ Assets │ │ Storage │
    │ Router │ │ (PGVec)│ │ Gen    │ │ (MinIO) │
    └────────┘ └────────┘ └────────┘ └─────────┘
```

## 🤖 Агенты и их роли

В LangGraph строим **циклический граф** с ветвлениями:

1. **`Planner`** — декомпозирует запрос пользователя в структуру курса (модули, темы, часы, целевая аудитория).
2. **`CompetencyMapper`** — строит карту компетенций по таксономии Блума + матрицу "тема × навык".
3. **`CurriculumDesigner`** — детализирует каждый модуль: цели, ключевые идеи, связи между темами.
4. **`LectureWriter`** — пишет конспекты лекций, скрипты, примеры кода.
5. **`SlideDesigner`** — конвертирует конспекты в слайды (Marp), генерирует диаграммы (Mermaid).
6. **`AssessmentDesigner`** — тесты (MCQ, code, open questions) + рубрикаторы + эталонные ответы.
7. **`VisualGenerator`** — превью-картинки, инфографика, схемы (Flux/Mermaid).
8. **`Reviewer`** (критик) — проверяет согласованность, полноту, сложность, возвращает на доработку.
9. **`Orchestrator`** — управляет состоянием, решает, когда курс "достаточно хорош".

Плюс **супервайзер** — агент, который ведёт диалог с пользователем, уточняет требования, показывает промежуточные результаты.

---

## 🔄 Пайплайн работы

```
1. User Request → Orchestrator
2. Orchestrator → RAG (поиск референсов, стандартов, примеров)
3. Planner → структура курса (JSON schema)
4. CompetencyMapper → матрица компетенций
5. [Loop до 3 итераций]:
     a. LectureWriter + SlideDesigner + AssessmentDesigner (параллельно)
     b. Reviewer → оценка + фидбек
     c. Если score < threshold → возврат на (a) с фидбеком
6. VisualGenerator → финальные иллюстрации
7. Packager → сборка в PDF/PPTX/SCORM/LMS-ready
8. Output → пользователю с возможностью редактирования
```

## 🛡️ Prod-ready практики (обязательно)

1. **Structured outputs везде** — Pydantic-модели на выходе каждого агента, JSON Schema валидация.
2. **Retry с экспоненциальным backoff** — через Tenacity + Temporal.
3. **Fallback модели** — если GPT-4.1 упал → Claude → локальная модель.
4. **Streaming ответов** — пользователь не ждёт 5 минут в тишине.
5. **Cost control** — лимиты на курс, алерты при превышении.
6. **Prompt versioning** — промпты в Git, не в коде.
7. **Eval-driven development** — каждый промпт-чейндж проходит через eval-датасет.
8. **PII redaction** — очистка пользовательских данных перед LLM.
9. **Audit log** — кто что сгенерировал, когда, какой моделью.
10. **Graceful degradation** — если визуал не сгенерировался — курс всё равно выдаётся.

## ⚠️ Риски и митигации

| Риск | Митигация |
|---|---|
| Галлюцинации в учебных материалах | RAG по проверенным источникам + факт-чекер агент + ссылки на источники |
| Несогласованность между модулями | Reviewer-агент с глобальным контекстом + schema-валидация |
| Дороговизна LLM | Кэширование, локальные модели для черновых задач, иерархия моделей |
| Долгое время генерации | Стриминг + параллелизация агентов + инкрементальная сборка |
| Качество тестов | Eval-набор из 500+ вопросов, сравнение с эталонными курсами |
| Юридические риски | Disclaimer, запрет на генерацию сертификационных экзаменов |

---

## 🚀 Что делает решение "ебанутым" (в хорошем смысле)

- **Self-improving**: каждый курс, который пользователь отредактировал, идёт обратно в RAG как референс.
- **Adaptive difficulty**: агент анализирует целевую аудиторию и подстраивает сложность.
- **Multi-modal output**: не просто текст, а слайды + видео-скрипты + код-сэндбоксы + интерактивные задания.
- **LMS-native**: генерация SCORM-пакетов, которые можно сразу залить в Moodle.
- **Коллаборация**: несколько пользователей могут совместно редактировать курс в реальном времени.
- **Analytics**: после запуска курса агент собирает фидбек и предлагает улучшения.

2. **Retry с экспоненциальным backoff** — через Tenacity + Temporal.
3. **Fallback модели** — если GPT-4o упал → Claude → локальная модель.
4. **Streaming ответов** — пользователь не ждёт 5 минут в тишине.
5. **Cost control** — лимиты на курс, алерты при превышении.
6. **Prompt versioning** — промпты в Git, не в коде.
7. **Eval-driven development** — каждый промпт-чейндж проходит через eval-датасет.
8. **PII redaction** — очистка пользовательских данных перед LLM.
9. **Audit log** — кто что сгенерировал, когда, какой моделью.
10. **Graceful degradation** — если визуал не сгенерировался — курс всё равно выдаётся.

## ⚠️ Риски и митигации

| Риск | Митигация |
|---|---|
| Галлюцинации в учебных материалах | RAG по проверенным источникам + факт-чекер агент + ссылки на источники |
| Несогласованность между модулями | Reviewer-агент с глобальным контекстом + schema-валидация |
| Дороговизна LLM | Кэширование, локальные модели для черновых задач, иерархия моделей |
| Долгое время генерации | Стриминг + параллелизация агентов + инкрементальная сборка |
| Качество тестов | Eval-набор из 500+ вопросов, сравнение с эталонными курсами |
| Юридические риски | Disclaimer, запрет на генерацию сертификационных экзаменов |

---

## 🚀 Что делает решение "ебанутым" (в хорошем смысле)

- **Self-improving**: каждый курс, который пользователь отредактировал, идёт обратно в RAG как референс.
- **Adaptive difficulty**: агент анализирует целевую аудиторию и подстраивает сложность.
- **Multi-modal output**: не просто текст, а слайды + видео-скрипты + код-сэндбоксы + интерактивные задания.
- **LMS-native**: генерация SCORM-пакетов, которые можно сразу залить в Moodle.
- **Коллаборация**: несколько пользователей могут совместно редактировать курс в реальном времени.
- **Analytics**: после запуска курса агент собирает фидбек и предлагает улучшения.
