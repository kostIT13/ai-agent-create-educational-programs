## 1. Задача и ключевая идея

**Задача.** Создать ИИ-агента, который по запросу пользователя:

- разрабатывает программу обучения по ИИ;
- учитывает заданные требования и референсы;
- определяет структуру обучения;
- формирует карту компетенций;
- генерирует тестовые вопросы и задания для семинаров;
- готовит план и визуальные материалы для лекций.

**Ключевая идея: не «чат с промптом», а конвейер вокруг единого графа курса.**

Слабое решение генерирует всё одним промптом и получает красивую воду и несвязанные артефакты. Сильное строится на **constructive alignment**: любая сущность в курсе трассируется по цепочке:

```
Компетенция → Результат обучения → Тема → Активность → Оценивание
```

**Источник правды один:** структурированный JSON-граф курса. Тесты, семинары, лекции и слайды генерируются из него, а не друг из друга. Это даёт:

- согласованность всех артефактов;
- возможность перегенерировать один модуль;
- автоматическую проверку покрытия;
- объяснимость (каждая сущность ссылается на источник).

## 2. Вход и выход системы

### Вход (бриф)

- тема и цель курса, аудитория и входной уровень;
- объём (часы, недели, формат: лекции / семинары / лабы), язык;
- требования: ограничения, обязательные темы, стиль преподавания;
- референсы: PDF, ссылки, существующие программы, стандарты (профстандарты, DigComp, ESCO, NIST AI RMF, EU AI Act и т. п.).

### Выход (пакет курса)

1. Учебный план и рабочая программа (модули, часы, пререквизиты)
2. Карта компетенций (матрица «компетенция × модуль» с уровнями по Блуму)
3. Банк тестовых вопросов (дистракторы, пояснения, сложность, привязка к результатам)
4. Семинары и лабы: задания, данные, рубрики оценивания, эталонные решения
5. Планы лекций: тайминг, ключевые тезисы, заметки лектора, примеры
6. Визуалы: слайды (.pptx), схемы, инфографика
7. Методичка для преподавателя + экспорт в LMS

## 3. Мультиагентный пайплайн

```
Бриф → [Intake] → [Reference Analyst] → [Competency Architect] ──► ✋ чекпоинт
     → [Curriculum Architect] ──► ✋ чекпоинт
     → параллельно: [Assessment] [Seminar] [Lecture]
     → [Visual Agent]
     → [Critic / QA] ⟲ (авто-доработка)
     → [Packager] → ZIP / LMS / PPTX / DOCX
```

| Агент | Что делает |
|---|---|
| **Intake** | Разбирает бриф, задаёт максимум 3–5 уточняющих вопросов, формирует спецификацию |
| **Reference Analyst** | Парсит референсы, строит RAG-индекс, извлекает темы, термины и требования стандартов |
| **Competency Architect** | Строит карту компетенций, формулирует измеримые результаты обучения (глаголы Блума) |
| **Curriculum Architect** | Модули, последовательность, граф пререквизитов, распределение часов |
| **Assessment Designer** | Вопросы разных типов и уровней, калибровка сложности, привязка к результатам |
| **Seminar Designer** | Практические задачи, кейсы, ноутбуки, рубрики, критерии успеха |
| **Lecture Planner** | План каждой лекции, примеры, вопросы для аудитории, заметки лектора |
| **Visual Agent** | Слайды и диаграммы (Mermaid/SVG), инфографика |
| **Critic / QA** | Проверка покрытия, дублей, нагрузки по часам, фактов, tone-of-voice; возвращает правки на доработку |

**Два человеческих чекпоинта** (после компетенций и после структуры) важнее всего: ошибка на этих этапах размножается на весь пакет.

## 4. Модель данных

Упрощённая JSON-схема графа курса:

```json
{
  "course": {"id": "...", "audience": "...", "hours": 72},
  "competencies": [{"id": "C1", "name": "...", "level": "apply"}],
  "outcomes": [{"id": "LO3", "competency": "C1", "bloom": "analyze", "text": "..."}],
  "modules": [{"id": "M2", "hours": {"lec": 4, "sem": 4}, "outcomes": ["LO3"], "prereq": ["M1"]}],
  "assessments": [{"id": "Q41", "outcome": "LO3", "type": "mcq", "difficulty": 0.6}],
  "seminars": [{"id": "S2", "outcomes": ["LO3"], "rubric": {}}],
  "lectures": [{"id": "L2", "module": "M2", "outline": []}],
  "sources": [{"id": "R7", "type": "pdf", "chunks": []}]
}
```

Каждая сгенерированная сущность хранит ссылки на `sources` и на результаты обучения. Отсюда матрица покрытия и объяснимость.

Состояние LangGraph = граф курса (Pydantic-модель):

```python
class Outcome(BaseModel):
    id: str
    competency_id: str
    bloom: Literal["remember","understand","apply","analyze","evaluate","create"]
    text: str
    source_refs: list[str]          # ссылки на чанки референсов

class CourseState(TypedDict):
    brief: Brief
    sources_index: str              # имя коллекции в Qdrant
    competencies: list[Competency]
    outcomes: list[Outcome]
    modules: list[Module]
    questions: Annotated[list[Question], merge_by_id]
    seminars: Annotated[list[Seminar], merge_by_id]
    lectures: Annotated[list[Lecture], merge_by_id]
    critic_report: CriticReport | None
```

## 5. Стек

Адаптирован под ваш текущий набор технологий.

### 5.1. Берём в ядро

| Слой | Выбор | Почему |
|---|---|---|
| Оркестрация | **LangGraph** | Граф с состоянием, чекпоинты, human-in-the-loop (`interrupt`), параллельные ветки (`Send`), персистентность в Postgres |
| Backend | **FastAPI + SQLAlchemy + Pydantic** | Pydantic-схемы = модель данных и контракт structured output |
| Основная БД | **PostgreSQL** | Граф курса, версии, джобы, чекпоинты |
| Векторная БД | **Qdrant + fastembed** | Нативный hybrid (dense + sparse) с RRF на стороне БД |
| Кэш / очереди | **Redis** (+ Arq после хакатона) | Прогресс, кэш, лимиты |
| LLM | **OpenRouter** + прямой API Claude | Сильная модель для архитектора и критика, дешёвая для массовых вопросов |
| Evals и трейсинг | **Langfuse + RAGAS** | Трейсы, стоимость, датасеты; faithfulness относительно референсов |
| UI | **React + TypeScript + React Flow** | Главный «вау» хакатона |
| Инфра | **Docker Compose + Nginx** | Хватит надолго |

### 5.2. Что не берём (чтобы не раздувать scope)

- **Milvus, FAISS, ChromaDB, sqlite-vec**: достаточно одной векторки (Qdrant). Дедупликацию вопросов можно делать отдельной коллекцией в Qdrant.
- **Arize Phoenix**: дублирует Langfuse.
- **Streamlit / Chainlit**: заменяются React-фронтом (Chainlit можно оставить как запасной быстрый UI).
- **LoRA/QLoRA**: не на хакатоне; идёт в roadmap.
- **Ollama**: только как опция «локальный режим» для закрытого контура.

### 5.3. Что докупить

| Задача | Инструмент |
|---|---|
| Парсинг референсов (PDF, DOCX, слайды) | **Docling** (или Unstructured) |
| Мультиязычный поиск (русский) | Эмбеддинги **bge-m3** / multilingual-e5, реранкер **bge-reranker-v2-m3** |
| Надёжный structured output | Нативный tool use / JSON schema + **Instructor** или Pydantic AI |
| Слайды | **python-pptx** (контроль) или **Marp** (быстро) |
| Схемы | **Mermaid CLI** (mmdc), Graphviz для графа пререквизитов |
| Документы | **python-docx** |
| LMS-экспорт | Moodle XML / GIFT (затем QTI 2.1) |
| Песочница для кода семинаров | Docker-контейнер с лимитами или E2B |
| Промпт-регрессии | **Promptfoo** (дополняет Langfuse) |

### 5.4. Frontend-стек

- **Vite + React + TypeScript**
- **Tailwind + shadcn/ui** (без кастомного дизайна, чтобы не тратить время)
- **React Flow** (граф агентов и граф курса)
- **TanStack Query**, **Zustand**
- **SSE** для стрима событий пайплайна
- **openapi-typescript**: генерация TS-типов из OpenAPI FastAPI (контракт Pydantic ↔ TS без ручной работы)

## 6. Архитектура и граф LangGraph

```
[React app]  ──REST + SSE──►  [FastAPI]
                                  │
                      BackgroundTasks ──► [LangGraph workflow]
                                  │
      ┌──────────────┬────────────┼───────────────┐
   Postgres        Qdrant       Redis          Langfuse
 (граф курса,    (референсы,   (кэш,          (трейсы, evals,
  версии,         hybrid +      прогресс)       промпты)
  checkpoints)    rerank)
```

### Топология графа

1. `intake` → `ingest_refs` (парсинг, чанкинг, индексация)
2. `competency_architect` → **interrupt** (человек правит карту)
3. `curriculum_architect` → **interrupt** (человек правит структуру)
4. Параллельно (`Send` API, по воркеру на модуль): `assessment`, `seminar`, `lecture`
5. `visual_agent` (слайды и диаграммы по планам лекций)
6. `critic` → при критических замечаниях возврат **только в проблемные модули**, максимум 2 итерации
7. `packager` → ZIP: PPTX, DOCX, Moodle XML, JSON

## 7. RAG-контур

- **Парсинг:** Docling → чанкинг по структуре документа.
- **Индекс:** Qdrant, dense (bge-m3) + sparse (BM25/fastembed).
- **Поиск:** hybrid-запрос с RRF → реранк топ-30 до топ-6 (bge-reranker-v2-m3).
- **В промпт:** чанки с id, обёрнутые в теги `<source>`.
- **Обязательство:** каждая сгенерированная сущность возвращает `source_refs`.
- **Проверка:** Critic проверяет, что утверждения следуют из указанных чанков (RAGAS faithfulness + собственный LLM-judge).
- **Свежесть:** веб-поиск для актуализации контента (ИИ устаревает быстрее других областей).

## 8. Качество и evals

### Автоматические проверки (Critic, детерминированные)

- каждая компетенция покрыта ≥ N результатами; каждый результат ≥ 1 оцениванием и ≥ 1 активностью;
- сумма часов совпадает с брифом;
- в графе пререквизитов нет циклов и «висящих» тем;
- распределение по уровням Блума соответствует уровню аудитории.

### Проверки качества (LLM-judge + эмбеддинги)

- вопросы: один правильный ответ, правдоподобные дистракторы, нет подсказок в формулировке, нет дублей (по эмбеддингам);
- фактчек: claim → источник (референсы + веб-поиск для свежих тем);
- исполнимость кода и ноутбуков семинаров (запуск в песочнице).

### Eval-набор

- 10–20 эталонных брифов с экспертной разметкой (на хакатоне: 3);
- LLM-as-judge с рубриками;
- RAGAS (groundedness);
- прогон в CI при изменении промптов (Promptfoo + Langfuse datasets);
- для демо: график «до/после Critic» на 3 брифах.

## 9. Frontend (React + TypeScript)

**Принцип: побеждает самая убедительная демка.** Жюри не увидит Qdrant и RAGAS, оно увидит интерфейс.

### Экраны по приоритету

| P | Экран | Что на нём |
|---|---|---|
| **P0** | Бриф + референсы | Форма, drag-and-drop файлов, кнопка «Сгенерировать» |
| **P0** | Live-пайплайн | Граф агентов (React Flow) со статусами: ожидает / работает / готово; лента событий; счётчик токенов и стоимости |
| **P0** | Чекпоинт компетенций | Редактируемая таблица; «принять» / «перегенерировать с комментарием» |
| **P0** | Граф курса + heatmap покрытия | Компетенции × модули × оценивание; красные ячейки = пробелы Critic |
| P1 | Карточка модуля | Вкладки: лекция, семинар, вопросы, слайды (превью) |
| P1 | Трассировка | Клик по сущности подсвечивает цепочку и показывает цитату референса |
| P1 | Чат с курсом | «Сократи до 24 часов» → подсвечиваются изменённые узлы |
| P2 | Экспорт, сравнение версий, три адаптации курса | |

**Heatmap и живой граф пайплайна дают 80% визуального эффекта. Начинайте с них.**

**Важный приём:** фронт стартует с первого дня на **моковом JSON**, соответствующем Pydantic-схеме. Подключение к backend сводится к смене URL.

## 10. Контракт API

```
POST /courses                     создать курс из брифа
POST /courses/{id}/refs           загрузить референсы
GET  /courses/{id}/events (SSE)   поток: node_started, node_finished, token_usage, critic_issue
GET  /courses/{id}                текущий граф курса
POST /courses/{id}/resume         ответ человека на interrupt (правки компетенций/структуры)
POST /courses/{id}/chat           команда на изменение курса
POST /courses/{id}/regenerate     {module_id, comment}
GET  /courses/{id}/coverage       матрица покрытия + проблемы
GET  /courses/{id}/export?fmt=pptx|docx|moodle
```

Всё держится на одном событии SSE: `{node, status, payload}`. Граф агентов на фронте просто подписан на него.

## 12. План хакатона

### Принципы

1. **Вертикальный срез вместо ширины.** Один курс (например, «ИИ для менеджеров, 36 часов») проходит весь путь: бриф → компетенции → структура → материалы → экспорт.
2. **Показываем процесс, а не результат.** Живой граф агентов, стриминг событий, правки человека на чекпоинтах.
3. **Трассируемость видна глазами.** Клик по вопросу → результат обучения → компетенция → цитата референса.
4. **У демо есть страховка.** Предгенерированный курс в БД + записанное видео.

### Что режем под хакатон

| Режем | Заменяем |
|---|---|
| Arq/Celery, Temporal | FastAPI `BackgroundTasks` + LangGraph `astream_events` |
| LoRA/QLoRA, Phoenix, Milvus, FAISS | не делаем; слайд «roadmap» |
| Мультитенантность, auth | демо-учётка или без неё |
| Moodle XML + QTI + Notion | **PPTX + DOCX + Moodle XML** (минимум: первые два) |
| Полный RAGAS-прогон | один график «до/после Critic» на 3 брифах |
| Версионирование с диффами | откат на предыдущий снапшот (JSON в Postgres) |

**Оставляем:** LangGraph с `interrupt`, Qdrant hybrid + rerank, Langfuse (бесплатный трейс-экран для демо), детерминированные валидаторы, Critic.

### Распределение времени (в долях, масштабируйте под свои часы)

| Доля | Работа |
|---|---|
| **10%** | Схемы Pydantic, OpenAPI → TS-типы, скелет репозитория, docker-compose, 2–3 брифа и референсы для демо |
| **25%** | Backend-ядро: intake → компетенции → структура на LangGraph + interrupt, валидаторы покрытия |
| **20%** | Параллельно: RAG (Docling → Qdrant → hybrid + rerank), генерация вопросов, семинаров, лекций с `source_refs` |
| **25%** | Фронт: P0-экраны на реальных данных (до этого работа на моках) |
| **10%** | Critic + экспорт PPTX/DOCX |
| **10%** | Демо-прогон, предзаготовка, видео-запас, питч |

### Ориентир для длинного (недельного) формата

| Неделя | Результат |
|---|---|
| 1 | Pydantic-модели, 3 брифа, Intake → компетенции → структура на LangGraph, чекпоинты, валидаторы покрытия |
| 2 | Ingest референсов (Docling → Qdrant), hybrid + rerank, вопросы и семинары с `source_refs`, Langfuse |
| 3 | Лекции + визуальный агент (Mermaid, PPTX), Critic с авто-доработкой, экспорт DOCX/PPTX/Moodle XML |
| 4 | Evals: набор брифов, RAGAS, CI-прогон; точечная перегенерация модуля, версионирование |
| 5 | React-интерфейс: граф курса, heatmap, редактор |
| 6 | Прод: auth, лимиты, учёт стоимости, Nginx, мониторинг, документация, демо |

### Распределение ролей (если команда ≥ 3 человек)

| Роль | Зона |
|---|---|
| Backend/Agents | LangGraph, промпты, валидаторы, Critic |
| RAG/Data | Docling, Qdrant, hybrid + rerank, референсы, evals |
| Frontend | React Flow, heatmap, SSE, экраны чекпоинтов |
| (опц.) Product/Pitch | Брифы, демо-сценарий, слайды, видео |

---

## 13. Сценарий демо (4–5 минут)

1. **Проблема (20 сек):** «Методист тратит недели на программу, а ИИ-курсы устаревают за месяцы».
2. **Бриф (30 сек):** вводите тему, загружаете профстандарт и существующую программу.
3. **Live-пайплайн (60 сек):** агенты зажигаются на графе, видны лента событий и стоимость.
4. **Чекпоинт (45 сек):** правите одну компетенцию вручную, система пересчитывает зависимое.
5. **Heatmap и трассировка (60 сек):** показываете пробел; клик по вопросу раскрывает цепочку до цитаты источника.
6. **Чат (30 сек):** «Сократи до 24 часов» → перестраиваются только затронутые узлы.
7. **Экспорт (20 сек):** открываете реальные PPTX и DOCX.
8. **Слайд про метрики (30 сек):** до/после Critic, groundedness, стоимость одного курса.

**Страховка:** кэшированный прогон + видео; в live показываем только перегенерацию одного модуля.

---

## 14. Фичи для «вау»-эффекта

1. **Heatmap покрытия:** интерактивная матрица «компетенции × модули × оценивание».
2. **Gap-анализ:** загружаете существующую программу, получаете пробелы относительно стандарта и рынка.
3. **Адаптация под аудиторию:** один курс в трёх вариантах (менеджеры / разработчики / студенты) из одного графа.
4. **Режим «разговора с курсом»:** «сократи до 36 часов», «добавь модуль по агентам»; пересчитываются зависимые артефакты.
5. **Живая актуализация:** еженедельный джоб проверяет устаревание тем и предлагает обновления.
6. **Экспорт в один клик:** PPTX, DOCX, Moodle/QTI, Notion.
7. **Система учится на правках методиста:** кнопки «плохой / хороший вопрос» → датасет для дообучения (LoRA/QLoRA в roadmap).

## 15. Прод: что учесть после хакатона

- **Асинхронность:** джобы (Arq/Celery/Temporal), прогресс-бар, возобновление после сбоя.
- **Стоимость:** кэширование промптов, дешёвые модели для массовых задач, лимиты на пользователя, учёт токенов по курсу.
- **Версионирование:** каждая правка = версия графа, дифф и откат.
- **Безопасность и права:** изоляция референсов по тенантам; защита от prompt injection (контент референсов = данные, не инструкции); ПДн в материалах; авторизация.
- **Авторские права:** пересказ и ссылки, не копирование; изображения: собственная генерация или лицензируемые.
- **Надёжность:** ретраи, валидация схем, fallback на другую модель, идемпотентность шагов.
- **Обратная связь:** разметка качества от методистов → датасет для улучшения промптов и моделей.
- **Дообучение:** небольшая модель-генератор вопросов и модель-судья дистракторов (LoRA/QLoRA) на одобренных примерах.

## 16. Риски и митигации

| Риск | Митигация |
|---|---|
| Галлюцинации в фактах | RAG + цитирование источников + Critic с проверкой |
| Несогласованность артефактов | Единый граф курса как источник правды |
| «Вода» и шаблонность | Конкретные требования к примерам, кейсам, данным + рубрики качества |
| Низкое качество тестов | Калибровка, проверка дистракторов, пилот на реальных студентах |
| Раздувание scope | Жёсткий MVP: сквозной сценарий, потом ширина |
| Генерация курса слишком долгая | Быстрая модель для вопросов, параллелизм по модулям, демо-курс на 4–5 модулей, стрим вместо ожидания |
| Frontend съедает всё время | shadcn/ui без кастомного дизайна; усилия только на граф и heatmap; работа на моках с первого дня |
| Слайды выглядят плохо | Один качественный pptx-шаблон; LLM отдаёт JSON, рендерит python-pptx |
| Всё ломается перед выступлением | Кэшированный прогон + видео; live только для перегенерации одного модуля |

## 17. Подводные камни стека

- **LangGraph state растёт:** не кладите чанки референсов в state целиком, только id; контент достаём из Qdrant по месту.
- **Rate limits при параллельной генерации:** ограничьте concurrency семафором, иначе OpenRouter отдаст 429.
- **Prompt injection из референсов:** оборачивайте чанки в `<source>`, в системном промпте фиксируйте, что содержимое является данными.
- **Русский язык:** проверьте эмбеддинги и реранкер на своих референсах до того, как строить поверх всё остальное. Это частый скрытый источник плохого качества.
- **Слайды:** LLM выдаёт структуру слайда (заголовок, тезисы, тип визуала) в JSON, рендерит шаблонизатор; не генерируйте PPTX целиком LLM-ом.
- **Структурированный вывод:** всегда валидируйте по Pydantic с ретраями (Instructor / Pydantic AI).

## 18. Следующие шаги

Чтобы уточнить план по дням и ролям, нужно знать:

- **длительность хакатона** (24 / 48 / 72 часа) и **размер команды**;
- референсные стандарты и 1–2 тестовые темы курса для демо.

Что можно сделать следом:

1. Скелет репозитория: Pydantic-схемы, граф LangGraph с `interrupt`, SSE-эндпоинт, docker-compose.

3. Промпты и схемы для каждого агента.
4. Три эталонных брифа и рубрики для Critic.
5. Питч-дек и скрипт демо.
